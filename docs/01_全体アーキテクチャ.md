# 01. 全体アーキテクチャ

## 1. 設計思想

1. **Google Sheets を「業務データベース」にする** — スタッフが慣れた画面で入力でき、専用ソフト不要。
2. **会計の正は freee** — 売上・経費の「確定値」は freee。Sheets は「管理会計・業務管理」用。
3. **ID で全てをつなぐ** — 作品・商品・顧客・案件・売上に一意の ID を振り、AI や将来システムでも扱える形にする。
4. **人が最終判断する（Human-in-the-loop）** — 自動化は「集計・下書き・リマインド」まで。送信・投稿・会計登録は人が実行。
5. **段階的に育てる** — Sheets → Apps Script → 必要に応じて Zoho / 専用 DB へ移行できる構造。

## 4. データの流れ（例：海外ギャラリーで作品が売れた場合）

```
1. 海外営業パイプラインで案件 DEAL-0012 を「成約」に更新（スタッフ）
2. 作品台帳 ART-2025-0031 のステータスを「売約済」に変更
3. 売上台帳に SAL-2026-0105 を登録（通貨 EUR → 為替表で円換算）
4. 在庫・入出庫に「委託先 → 顧客」出庫を記録
5. freee で請求書発行（人が操作）→ freee 取引ID を売上台帳に記入
6. 入金後、freee（読み取り）と売上台帳を自動突合 → 入金済チェック
7. ダッシュボードに自動反映（地域別・チャネル別売上）
```

## 5. 権限設計（スタッフ利用を前提）

| データ | ai（代表） | スタッフ | バイト | 外部PD | AI連携 |
|---|---|---|---|---|---|
| 作品台帳 | 編集 | 編集 | 閲覧（原価列は非表示） | 閲覧 | 読取 |
| 商品マスタ | 編集 | 編集 | 閲覧 | 閲覧 | 読取 |
| 顧客・取引先 | 編集 | 編集 | 発送先のみ閲覧 | 法人のみ閲覧 | 読取（個人情報はマスク） |
| 売上台帳 | 編集 | 編集 | ― | 集計のみ | 読取 |
| 経費台帳 | 編集 | 編集 | 自分の立替のみ入力 | ― | 読取 |
| 在庫・入出庫 | 編集 | 編集 | 入力 | ― | 読取 |
| 海外営業 | 編集 | 編集 | ― | 編集 | 読取 |
| ダッシュボード | 閲覧 | 閲覧 | ― | 閲覧 | 読取 |
| freee | 管理者 | 閲覧/一部 | ― | ― | **読取専用 API のみ** |

実装方針：Sheets は **ファイル単位で共有範囲を分ける**（1ファイルに全部入れない）。
例：「顧客DB」ファイルはバイトに共有せず、発送用の「発送リスト」だけを別シートで `IMPORTRANGE` 参照。

## 6. 技術選定（段階別）

| 段階 | 技術 | 理由 |
|---|---|---|
| Phase 1 | Google Sheets ＋ データ入力規則（プルダウン） | 学習コストゼロ、スタッフ即利用可 |
| Phase 2 | Google Apps Script（GAS） | Google 内で完結。ID 自動採番・リマインド・集計 |
| Phase 2 | Looker Studio | 無料のダッシュボード、Sheets を直接参照 |
| Phase 3 | freee API（読み取りスコープ）| 会計データの自動突合 |
| Phase 4 | ChatGPT / Muse 等の AI | 下書き・翻訳・分析。データは CSV/JSON で受け渡し |
| 将来 | Zoho CRM ／ 専用 DB | 顧客数・案件数が Sheets の限界を超えたら |

**移行判断の目安**：顧客 3,000 件超、月間取引 300 件超、同時編集者 5 名超 のいずれかで Zoho 等への移行を検討。
